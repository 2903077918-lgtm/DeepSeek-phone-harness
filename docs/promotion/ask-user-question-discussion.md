# Agent 反问一次，任务就卡死 10 分钟：你们怎么处理「ask_user_question」的？

> 一个真实的技术痛点，想知道社区都是怎么解决的。我先抛砖引玉，附上我的方案和踩过的坑。

---

先问大家一个问题：**你们用的 Agent 会突然反问用户吗？反问之后任务怎么办？**

我遇到的情况是这样的：DeepSeek Harness 的 Agent 在干活时会调用 `ask_user_question` 工具——比如"这个模块要改成同步还是异步？""要不要执行这条高风险命令？"。听起来很合理，但一开始它把我的**整个任务队列卡死了 10 分钟**。

## 问题：反问 = 静默卡死

最坑的是**它不报错**。任务就挂在那，`pending` 一直 +1，你以为它在思考，其实它在等一个永远不会有人回答的问题——因为反问走的是**提问通道**（`question/requested`），跟审批通道（`approval/requested`）**完全不是一回事**。

我第一版中继只监听了审批通道，所以：

```
Agent 在电脑上停下，等用户回答
      ↓
提问通道的消息被我的中继直接丢弃
      ↓
手机端毫无感知
      ↓
任务永久挂起，直到超时
```

我用了两天才定位到：不是 DSH 挂了，是**反问没被转发到人那里**。

## 我的方案：提问变成「需要你回答」卡片

做 [DeepSeek Phone Harness](https://github.com/2903077918-lgtm/DeepSeek-phone-harness)（手机远程控制电脑 Agent）时，我把提问也做成了一个**卡片**直插消息流：

- Agent 反问 → 手机弹出「需要你回答」卡
- 可以选选项 / 输入自定义答案 / 跳过
- 回答完任务自动继续，不回答就等着

协议层要和官方 Web GUI 完全一致（`{ok:true, value:{sessionId, answer:{answers:[{id, selected}]}}}`），否则 DSH 不认。

## 更想听你们的

我的方案解决了"手机端"，但我更想知道社区更广的实践：

1. **你们让 Agent 反问用户吗？还是直接禁用 ask_user_question？**
2. **反问的粒度**：哪些问题值得问人？哪些其实可以自己决定（避免打断）？
3. **异步的处理方式**：反问挂起时，任务队列怎么处理？是阻塞、跳过、还是并行？
4. 有没有人给 Agent 设了"反问上限"或用别的工具替代？

老实说，我现在的做法偏保守（能自己判断就不反问，反问必定打断）。但我很怀疑这不是最优解——**"什么时候该打断用户"可能比"怎么打断"更重要**。

欢迎在下面聊聊你们的实践。如果你们也有"Agent 反问导致任务卡死"的经历，报个到我统计下这个坑有多普遍。
