# Agent 的下一站是口袋：为什么"手机端"可能是 Agent 最好的形态之一

> 我们把 Agent 从终端搬进浏览器，现在该把它搬进口袋了。这不是"移动端适配"，是交互范式的一次迁移。

---

最近 DeepSeek Harness 开源，社区一片沸腾——模型、工具、Agent Loop 全是插件，自由度拉满。但热闹之下我注意到一件事：

> 大家都在讨论 Agent **能做什么**，很少有人讨论 Agent **你在哪用**。

我想聊聊后者，顺便给一个我自己的回答。

## Agent 的使用场景，正在从"坐下"变成"随时"

第一代 Agent 使用方式：打开终端，坐下，盯着看。

第二代（Web GUI）：打开浏览器，坐下，盯着看。

本质上还是**"人必须坐在电脑前"**。但 Agent 的价值恰恰是"替你干活"——活是它干的，你却要一直陪着它，这合理吗？

- 通勤路上，我想让它先跑起来
- 睡前，我想给它派明天的活
- 开会中，它要个授权，我想点一下就放行

这些场景的共同点：**人不坐在电脑前，但 Agent 在工作。** 谁来当这个"遥控器"？手机是唯一答案。

## 手机端不是"缩小版网页"，是新的交互范式

很多人以为手机端 = 网页缩小。真做完之后我发现，**手机端的交互逻辑和网页端完全不同**：

**1. 从"多窗口"到"单时间线"**

网页端是多个面板并存：会话、工具输出、审批弹窗。手机端天然只有一条**纵向时间线**——用户消息、Agent 推理、工具卡片、审批卡、提问卡，全部线性排列。Agent 的工作过程变成了一条**可回放的流水线**，反而更清晰。

**2. 从"点击"到"决策"**

网页端你习惯到处点。手机端拇指操作半径有限，逼着你把交互收敛成**"看一眼 → 做决策"**：这个工具调用要不要放行？这个问题怎么回答？——全是判断题，不是浏览题。

**3. 从"陪伴"到"异步"**

网页端你陪着 Agent 干完。手机端你是**派活-离开-回来收结果**。这逼着 Agent 端做好状态管理（任务队列、结果留存、失败通知）——这其实是 Agent 产品成熟的方向。

## 我的回答：一个把 Agent 装进口袋的开源项目

基于上面的思考，我做了 [DeepSeek Phone Harness](https://github.com/2903077918-lgtm/DeepSeek-phone-harness)：

- 手机浏览器直接控制电脑上的 DeepSeek Harness（4G/5G，Tailscale 直连）
- 流式输出、工具卡片（带路径/状态/详情）、审批、提问回答、模型切换、终端、文件
- 零 npm 依赖，4000 行，一个 HTML 文件搞定前端
- 开源 MIT，克隆即用

它不是什么颠覆性发明，只是一个朴素的回答：**"Agent 替你干活的时候，你应该可以不在场。"**
