# 从"躺在床上想派活"到开源：这个项目的一周开发日记

> 没有华丽的开始，只有一个深夜的念头。记录 DeepSeek Phone Harness 从 0 到发布的一周。

---

## Day 1 · 凌晨 1 点，一个念头

那天晚上我躺在床上，突然想到可以让电脑上的 Agent 提前跑一个任务。起床去书房？太麻烦。放弃？不甘心。

那个瞬间我意识到：**Agent 的价值在于替我干活，但我却被绑在电脑前。**

第二天一早，我打开编辑器，决定自己解决这个问题。

## Day 2 · 第一版：一个能通的"翻译官"

核心思路很简单：手机发 HTTP 请求，Agent 进程翻译成 DSH 的 RPC，DSH 的响应再翻译回去。

当天晚上，第一版通了：手机发一句话，电脑上的 Agent 执行，结果回到手机。**虽然丑，但它动了。**

## Day 3 · 卡死一整天：ask_user_question

第三天，任务开始"随机卡死"。排查到深夜才发现：**Agent 会反问用户，反问不走审批通道，而我没监听提问通道。** 任务永远等一个没人回答的问题。

修好那一刻，我在提交信息里写了三个字："不卡了"。

## Day 4 · 让"干活的过程"可见

光有结果不够——我想让手机看到 Agent **每一步在干什么**。

于是有了工具卡片：每个工具调用一张卡，显示图标、状态、操作的文件路径，点开看完整参数和结果。Agent 的思考过程也折叠展示。

那天晚上我盯着手机看 Agent 干活看了很久。**"看见它在想、在动"和"等一个结果"，是两种完全不同的体验。**

## Day 5 · 终端、文件、任务：从"能用"到"好用"

补齐了终端（远程敲命令）、文件浏览、任务列表（一键重跑）、会话管理（重命名/删除/搜索）。

## Day 6 · 打磨细节

- 审批卡、提问卡直接插进消息流，不打断上下文
- 模型选择面板、图片附件、思考折叠
- 修了浏览器缓存导致的"永远看不到新界面"

## Day 7 · 开源发布

写 README、写宣传文、推上 GitHub。发布那一刻没什么仪式感，就是 `git push` 然后长舒一口气。

**4000 行，零 npm 依赖，一个 Node 进程 + 一个 HTML 文件。**

## 一周后的现在

它已经稳定运行：地铁上派任务、睡前改参数、开会时点审批。手机变成了 Agent 的遥控器——**"人在哪，Agent 就在哪"**，这句话不再是一句口号。
