# 同一时刻，让手机和电脑同时盯着 Agent 干活——结果我回不去了

> 你以为手机端是网页端的"缩水版"？我做完实测之后发现：有些体验，手机端反而更好。

---

做 DeepSeek Phone Harness 之前，我给自己定了个验收标准：**手机端至少要达到网页端 80% 的体验，否则不算做完。**

做完之后我做了个对照实测：同一个任务，电脑浏览器和手机浏览器同时打开，观察 Agent 干活。结果有点出乎意料——**有几个体验，手机端反而更好。**

## 实测：同一个任务，两边同时看

任务：让 Agent 读取项目配置、总结当前进度、顺手跑一个测试。

| 维度 | 电脑网页端 | 手机端 |
| --- | --- | --- |
| 流式输出 | 正常 | 正常（打字机效果） |
| 工具调用可见性 | 有 | **有，且更强**：每张卡显示文件路径，点开看参数+结果 |
| 审批 | 弹窗/面板 | **卡片直插消息流**，不用切页面 |
| 提问回答 | 输入框接管 | **选项卡片**，点一下就行 |
| 模型切换 | 下拉菜单 | 底部面板，拇指可及 |
| 离开场景 | 必须人在电脑前 | **躺着也能操作** |

## 为什么手机端某些体验反而更好

### 1. 审批/提问不打断上下文

网页端审批是一个独立弹窗，会打断你正在看的内容。手机端我把审批和提问做成了**卡片，直接插在消息流里**——Agent 干活到哪一步、为什么需要授权、为什么问这个问题，上下文是连续的。

### 2. 工具卡片天生适合竖屏

"读文件 → 跑命令 → 改代码"这种纵向的工具调用序列，**竖屏天然合适**。电脑上你要么看日志要么看列表，手机上是一条清晰的时间线：

```
[📄 read]   C:/.../config.json          ● 完成
[⚙️ pwsh]   npm test                    ● 运行中…
```

### 3. 拇指就是最好的鼠标

模型切换、附件添加、卡片展开——全是拇指操作半径内的东西。

## 一个诚实的对比结论

手机端不是网页端的替代品——**重活（改代码、查日志、开终端多开）当然还是电脑舒服**。但手机端补上了网页端最大的短板：**你不在电脑前的时候**。

- 通勤路上派任务，到站看结果
- 睡前改个参数，第二天醒来已验证
- 开会时 Agent 请求授权，手机点一下放行

**"人在哪，Agent 就在哪"** ——这才是手机端真正的价值，不是"更小的网页"。
