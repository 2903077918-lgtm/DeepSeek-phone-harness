# 手机远程控制电脑上的 Agent：你们觉得最该防的安全坑是什么？

> 一个开放性安全讨论，想收集社区真实顾虑。我先讲四个我实际踩到/想到的坑。

---

远程控制一直是个"方便 vs 安全"的拉扯。把手机变成电脑上 Agent 的遥控器之后，我整理了几个**真实的**安全顾虑，想听听大家的完整清单——肯定有我没意识到的。

## 我目前防住的三个

做 [DeepSeek Phone Harness](https://github.com/2903077918-lgtm/DeepSeek-phone-harness)（4G/5G 下手机操作电脑 Agent）时，我至少处理了三层：

1. **令牌鉴权**：所有接口要 `Authorization: Bearer`，令牌自己在本地 `config.json` 配，不进任何代码仓库（history 里清过一遍）。
2. **审批卡**：Agent 要执行高风险操作（写文件、跑命令之前）→ 手机上先弹「需要授权」，允许/拒绝人说了算。我认为这是远程控制的**底线**——人不在电脑前，授权必须能拦截。
3. **网络隔离**：推荐 Tailscale 私有网络直连，不把端口裸暴露公网；公网走反向代理 + 强令牌。

## 但我更担心"没意识到的"

这几个是我心里没底的，欢迎拍砖：

- **4G/5G 环境下的中间人**：Tailscale 加密了，但如果不走 Tailscale 直接暴露，令牌在 HTTP 上是否安全？
- **Agent 越权的边界**：审批卡只能拦"我知道要拦的"。Agent 会不会通过组合低风险操作达成高风险结果（比如先读一堆文件再悄悄写一个）？
- **手机丢失**：手机解锁就能控制电脑 Agent——是不是该加二次验证 / 设备 PIN / 过期令牌？
- **模型自身被诱导**：如果我发给 Agent 一个精心构造的 prompt，它会不会执行超出预期的操作？审批粒度到底怎么控？

## 最想听你们的

远程控制工具的安全清单，社区才是最全的。想让大家聊聊：

1. 你远程控制自己的电脑时，**最担心哪一类风险**？
2. 除了"授权拦截"，还有什么**必要**的安全机制？
3. 你对"手机控制电脑"这类工具，**一句话劝退**会是什么？

我想把这个讨论沉淀成一份**开源远程控制工具安全 checklist**（好用的话整理进项目的 SECURITY.md），所以每条回复都会看、会引用。
