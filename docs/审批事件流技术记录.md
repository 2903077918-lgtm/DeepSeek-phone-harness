# 审批事件流技术探测记录（2026-08-14）

## 结论
DSH 的审批/事件推送端点 `/api/events.mux` 使用 **WebSocket**，不是 SSE：
- `fetch('http://127.0.0.1:3080/api/events.mux')` → 426 "upgrade required"（即使是 SSE 头）
- `new WebSocket('ws://127.0.0.1:3080/api/events.mux')` → 连接成功，**无需鉴权**（本地端口）
- 帧格式（JSON 文本）：`{type:'server-request', rpcId:'<uuid>', method:'<事件类型>', payload:{...}}`
  - method 取值示例：'session/subscribed'、'approval/requested'
  - 审批帧 payload：`{type:'approval/requested', sessionId, approvalId, toolName, callId?, reason?}`

## 审批回传协议
- `POST http://127.0.0.1:3080/api/respond`（HTTP，非 WS）
- body：`{type:'client-response', rpcId:'<审批帧外层的rpcId>', result:{ok:true, value:{sessionId, approvalId, outcome}}}`
- outcome 只允许：'allowed-once' | 'rejected'
- rpcId 必须等于审批帧外层 envelope.rpcId（pending 表按它索引）

## 实现要点（Agent E）
- Node 22+ 全局 WebSocket（零依赖）
- 常驻连接 → 解析 approval/requested → 存 pending 表（approvalId → {rpcId, sessionId, toolName, ...}）
- onclose/onerror → 指数退避重连
- /api/approvals GET（列表）/ POST（{approvalId, outcome} 回传）
