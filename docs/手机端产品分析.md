# 手机端产品分析：如果我是 Harness 开发团队

> 视角：DeepSeek Harness（DSH）开发团队，审视"手机端应该怎么做"
> 基于：DSH web 前端完整功能面 + 后端服务能力 + phone-harness 现状（2026-08-14）

---

## 一、DSH 现在有什么（能力全景）

### 前端（web UI 功能模块）
- **对话核心**：conversation（消息流、流式、Markdown）、attachment（图片/文件）、tool/trajectory（工具调用轨迹）、message-feedback（反馈）
- **工作区**：workspace（多项目）、sidebar（侧边栏）、directory-picker（目录选择）
- **会话管理**：fork/resume（分叉/恢复）、subagent（子代理树）、commands（斜杠命令）
- **规划执行**：plan（计划模式）、goal（目标）、jobs（后台任务）、workflow-run（多 Agent 工作流）、todo
- **模型**：model-selection（provider/模型/推理级别切换）
- **治理**：permission-presets（权限预设）、user-questions（用户提问）、agent-preset（Agent 预设）
- **设置**：settings（通用/模型/插件/插件清单）、skill（技能）、theme（主题）
- **其他**：input-trigger、user-questions、deliverables（交付物）

### 后端服务（能力支撑）
- Agent 循环（agent-loop）、Agent 预设、默认模型
- 工具集：bash/pwsh/fs/fs-search/web/skill/subagent/workflow/goal/jobs/ask-user/str-replace-editor/ralph/todo
- 目标（goal + round-driver）、作业（jobs）、工作流（workflow + worker-thread）
- 计划模式、权限预设、技能（skill + filesystem）、命令、压缩（compact）
- 会话：事件源模型、持久化（zstd jsonl）、查询（sqlite）、审批、标题、遥测

### 核心设计理念
1. **事件源会话**：一切可回放、可重放
2. **深度 Agent 能力**：子代理、工作流、目标、后台任务（不只是聊天）
3. **治理完整**：权限分级、审批、计划模式、用户确认
4. **多项目工作区**：按 cwd 组织会话

## 二、手机端 vs 桌面端的本质差异

| 维度 | 桌面端（web） | 手机端 |
|---|---|---|
| 屏幕 | 大屏，多栏 | 小屏，单栏，手势 |
| 输入 | 键盘+文件拖拽 | 触屏+语音+照片 |
| 场景 | 深度开发、长时间 | 碎片时间、随时查看/下发 |
| 网络 | 本地稳定 | 移动网络、可能断连 |
| 注意力 | 专注 | 低介入（推送、通知） |

**结论**：手机端**不是桌面端的缩小版**，而是"**口袋里的远程控制台**"——核心价值是：人在外面，电脑上的 Agent 在工作，手机随时看进度、下发指令、处理审批。

## 三、手机端产品设计建议（Harness 团队视角）

### 核心定位：远程控制台，不是完整 IDE

**手机端只做 4 件事**（优先级排序）：

| 优先级 | 能力 | 为什么 |
|---|---|---|
| **P0** | 对话流 + 流式输出 + 审批 | 最核心：看 Agent 干活、干预 |
| **P0** | 会话/项目浏览 + 继续会话 | 随时随地接上电脑的活 |
| **P1** | 通知推送（任务完成/需审批） | 低介入体验的关键 |
| **P1** | 简单指令（发任务/斜杠命令） | 快速下发 |
| **P2** | 子代理树/任务队列可视化 | 了解 Agent 在干什么 |
| **P2** | 模型切换/权限控制 | 远程管理 |

**不做**（留给桌面）：复杂文件编辑、多栏布局、深度调试、完整设置。

### 信息架构（对标 iOS 习惯）

```
Tab 1 · 会话（对话流，默认页）
  ├─ 当前会话消息流（流式+工具卡+审批卡）
  ├─ 下拉：项目/会话切换器（类似 iOS 邮件滑动）
  └─ 底部：Composer（输入+附件+斜杠命令）

Tab 2 · 项目（工作区列表）
  ├─ 每个项目：会话数、最近会话预览
  └─ 点进：会话列表（标题/时间/消息数）

Tab 3 · 任务（Agent 活动）
  ├─ 运行中的任务（进度、工具调用、耗时）
  ├─ 后台作业（jobs）
  └─ 子代理树（可视化）

Tab 4 · 我的（设置）
  ├─ 连接状态（Tailscale/隧道）
  ├─ 模型选择、权限预设
  ├─ 通知设置
  └─ 审批历史
```

### 关键交互设计

1. **流式输出 + 中断**：打字机渲染；长按时可"中断任务"（control.kill）
2. **审批卡片**：工具名/原因/参数摘要 → 允许一次/拒绝/超时默认拒绝
3. **通知推送**：`任务完成`、`需要审批`、`出错`——手机锁屏也能感知
4. **语音输入**：手机天然优势，说一句就是一条指令
5. **图片附件**：手机拍照/相册 → 作为 Agent 输入（DSH 已支持 image attachment）
6. **离线提示**：断连时显示缓存的任务状态，重连自动同步

### 安全模型（远程 = 高信任）

- **端到端加密**：任务内容服务器不可读（X25519 + AES-GCM）
- **配对**：电脑生成配对码 → 手机确认（QR 或码）
- **审批**：高风险操作必须手机确认；control.kill 紧急停止
- **设备管理**：远程注销、设备列表

## 四、phone-harness 现状 vs 建议（差距）

| 建议能力 | phone-harness 现状 | 差距 |
|---|---|---|
| 对话流+流式 | ✅ 已实现（v2） | 流式已修（kind 枚举） |

| 继续会话 | ✅ 已实现（dsh-continue） | — |
| 审批 | ✅ 已实现（WS 转发+卡片） | 权限配置下触发少 |
| 通知推送 | ❌ 未做 | 需云端（阶段3） |

| 语音输入 | ❌ 未做 | 前端 PWA + Web Speech |
| 图片附件 | ❌ 未做 | 需 session.attachment API |
| 模型切换 | ❌ 未做 | 需 session.models API |
| 端到端加密 | ❌ 未做 | 阶段3（云端） |
| 中断任务 | ❌ 未做 | 需 session.cancel API |

## 五、路线建议（Harness 团队会怎么做）

**如果我是 DSH 团队**，手机端会走：
1. **先做"远程控制台"最小闭环**（对话+流式+审批+通知）——这是用户最痛的
2. **复用桌面端全部后端 API**（session/approval/events 都是现成的），手机端只是新前端
3. **安全优先**：E2EE + 配对 + 审批，从第一天就设计进去
4. **PWA 先行**（绕过上架审核），验证后再原生 App

**phone-harness 正好踩在这个思路上**，且已实现大部分。差距主要在：通知推送（需云端）、任务可视化、语音/图片输入——这些是 P1/P2，云端阶段（阶段3）一并做。

---

## 六、给我们的行动建议

按优先级：

1. **完成 UI 适配**（kind/messageCount/ungrouped——后端已就绪，UI 差一步）
2. **补"中断任务"**（session.cancel API，手机长按中断——交互刚需）
3. **补"任务可视化"**（后端 subagent.list + jobs API → 手机"任务"Tab）
4. **云端阶段**（通知推送 + E2EE + 配对——产品化的关键）
5. **PWA 包装**（可安装到手机桌面，接近 App 体验）
