## 二、普遍共识（多数项目一致，直接采用）

1. **agent 机器反向出站，不开入站端口**：`wrapper/daemon` 主动连中继/云端；NAT/家庭带宽天然穿透（cloude 隧道、cc-remote 出站、AgentFlow 两端出站、hapi relay）。
   → **项目已同向**：Agent `src/transport/cloud.mjs` 就是反向出站连 cloud-relay。✅ 无需改。
2. **连接用 WebSocket/SSE 流式，不用轮询**；断线后按 `seq/after_seq` 增量补尾巴，事件带自增序号（cloude NDJSON seq、AgentFlow Envelope seq、hapi socket.io 自同步）。
   → cloud-relay 的 RelayDO 已用 WebSocket + 信封 msgId/seq（`src/protocol.js`）；手机端应复用同一 seq 语义做断线续传。
3. **配对 = 一次性兑换码/二维码 + 短生命周期、可撤销的设备凭证**，绝不永久共享 token（cloude 单 token 是公认短板；cc-remote/AgentFlow 都有可撤销设备凭据）。
   → 项目已有 `pair_codes`（Agent 生成配对码、15 分钟 TTL、只存哈希、手机用码绑定 device↔user）+ devices 表。✅ 直接复用 `/v1/devices/register` + `/v1/devices/:id/pair`。
4. **消息流 = 流式打字机 + 可折叠过程（reasoning/计划/命令/diff）+ 底部状态条**（模型/权限/思考强度/上下文占用）。
   → 现有 `web/index.html` 已实现深色流式对话 + 工具卡 + 审批卡，可复用到 cloud.html。
5. **任务队列有界、断线不丢**：后端持有排队任务，重连回摘要（cc-remote wrapper 有界队列、AgentFlow outbox TTL+去重）。

## 三、值得借鉴的高级做法（结合本项目落地）

1. **审批用「风险分级 × 执行边界」两轴**（cc-remote）
   - 已有 `guard.js` 的 low/medium/high 分级 → 决定"是否弹确认"；
   - 另一轴 = 执行边界/能力包（Read/Exec/Network/FullAccess）决定"动作能碰什么"。
   - 本项目落地：confirmation 卡片同时显示【风险级】+【动作类型(文件/命令/网络)】，高危才弹 E2E 签名确认，低危自动放行。

2. **设备→会话(任务)→对话 双层/三层导航**（hapi Machines→Sessions、“设备列表”）
   - 项目落地 cloud.html：**设备列表(云端手机端控制它的电脑) → 点进设备 → 该设备下的任务/对话**；云端 agent 与本地一并呈现。这正好匹配 cloud-relay 的 `devices` + `tasks` 资源模型。

3. **E2E 用浏览器原生 WebCrypto 可用的曲线**（AgentFlow 用 **P-256 ECDH**，cloude 无 E2E 是短板）
   - ⚠️ 重要：本项目后端 `e2ee.js` 用的是 **X25519**（Node/workerd little 支持，但**浏览器 WebCrypto 对 X25519 支持不全**）。
   - 为让**手机 web 在浏览器里做 E2E** 可行，云端 E2E 需**补一个 P-256(ECDH + HKDF + AES-GCM) 兼容路径**，或确认浏览器支持。→ cloud.html 第一版先把 E2E 后置，先打通连接/账号/设备，E2E 单独一步（后述）。

4. **配对阶段做「带认证的公钥交换 + 短生命周期设备 token」**（AgentFlow 裸 ECDH 无指纹是短板）
   - 手机拿配对码绑定后，云端为设备签发短期 deviceToken（可撤销）；公钥交换叠加用户显式确认（指纹/比对），杜绝中继换钥。

5. **断线重连：代际号丢弃过期 socket + 出站信封排队去重 + 状态机 connect→auth→catch-up→stable**（AgentFlow 很工程化）
   - 本项目 `cloud.mjs`/RelayDO 已有 `generation` 防过期回调 + outbox 回执，手机端沿用同样心智。

## 四、与我们已有后端 /v1/* 的映射（cloud.html 直接调用）

| 手机端能力 | cloud-relay 端点 | 已有后端模块 |
|---|---|---|
| 账号注册/登录 | `POST /v1/auth/register` / `login` | `store.ts` PBKDF2 密码哈希 |
| 云端地址/连接状态 | `GET /v1/status` | `index.ts` |
| 设备列表 | `GET /v1/devices/:id`；`GET /v1/tasks?deviceId=` 推断 | `store.ts` listTasks/getDevice |
| 设备配对 | `POST /v1/devices/register` → 配对码；`POST /v1/devices/:id/pair` | `store.ts` pair_codes |
| 任务下发 | `POST /v1/tasks` {deviceId, promptCipher} | `store.ts` createTask |
| 任务列表/详情 | `GET /v1/tasks` / `GET /v1/tasks/:id` | `store.ts` |
| 审批确认 | `POST /v1/tasks/:id/confirm` {decision} | `store.ts` updateTaskStatus |
| 取消/停止 | `POST /v1/tasks/:id/cancel` | store |
| 风险分级 | 后端 `guard.js` 可复用 | Agent 侧已有；云端按 riskLevel 字段 |

## 五、cloud.html 设计决策（据此实现）

**形态**：独立单页（连 cloud-relay），与现有连 LAN 的 `index.html` 并存、零回归。

**手机端页面结构（三层，含"云端来源"切换）**：
1. **首页/设备**：云端地址配置 + 账号（注册/登录）+ 设备列表（在线状态、已配对、kill 状态）+ 配对入口（输入设备 agentId + 配对码）
2. **设备 → 任务/对话**：选设备后进入其任务列表；点任务进对话（流式消息、结果、审批卡片）
3. **对话页**：消息流 + 输入框 + 审批确认卡（允许本次/拒绝）+ 状态条

**MVP 验收（cloud.html 第一版）**：连接云端(`/v1/status`) → 注册/登录 → 列出/配对设备 → 下发一个明文任务（E2E 后置）→ 看到任务状态/结果 + 审批确认接口可调。

**E2E（下一步，单列）**：浏览器 WebCrypto 做 P-256 ECDH + HKDF + AES-GCM（云端后端两侧补齐 P-256 兼容），配对时公钥指纹由用户确认；此步后任务 prompt 走密文。
